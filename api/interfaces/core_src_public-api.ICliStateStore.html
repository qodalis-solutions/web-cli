    Interface ICliStateStore

    Reactive state store scoped to a command processor or module.

    State is a plain object (Record<string, any>). Updates are shallow-merged (top-level keys are replaced, nested objects are not deep-merged). getState() returns a shallow copy: assigning its top-level keys has no effect, and nested objects must not be mutated in place either; always use updateState() to change state.

    Saved state is loaded once, before the store's command first runs (or by initialize()), and merged over the initial state, so keys added to the initial state later are present. Changes are saved with persist(), or after every change with autoPersist.

    A store is global by default: one saved state shared by every terminal and tab of the browser. A save writes only the top-level keys this terminal changed (merged into what is saved, under a cross-tab lock), so terminals changing different keys never overwrite each other; for the same key the last save wins. Changes saved elsewhere are applied here, except keys changed here and not saved yet. A store with scope: 'session' belongs to one terminal and is never saved.
