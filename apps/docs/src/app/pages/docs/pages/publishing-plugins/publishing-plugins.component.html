Publishing a plugin

Plugins are published to npm, as any package. The plugin marketplace indexes them from there: it reads package.json, records the hash of the browser bundle and which CLI version each release needs, and lists a plugin once a moderator has reviewed it. Users then find it with pkg browse / pkg search and install it by its short name with pkg add. The marketplace never hosts code.

1. Mark the package

Plugins scaffolded with @qodalis/create-cli-plugin already have all of this. For an existing plugin, add to package.json:

  • The keyword qodalis-cli-plugin: the marketplace's indexer searches npm for it.
  • A browser bundle: unpkg, umd or main (read in that order, a .js file) pointing at the IIFE build that registers the module. A package without one is rejected.
  • The peer dependency on @qodalis/cli-core, and optionally a qodalis block.
package.json 
{
  "name": "@acme/cli-weather",
  "keywords": ["qodalis-cli-plugin"],
  "unpkg": "dist/umd/index.global.js",
  "peerDependencies": { "@qodalis/cli-core": "^2.8.0" },
  "qodalis": {
    "apiVersion": 2,
    "category": "tools",
    "icon": "assets/icon.svg",
    "screenshots": ["assets/shot-1.png"],
    "serverPackages": [{ "ecosystem": "npm", "name": "@acme/cli-server-plugin-weather" }]
  }
}
Field Meaning
apiVersion The module API the bundle needs (the apiVersion of your ICliModule, today 2). Without it the marketplace takes the major of the core peer range (^2.8.0 → 2), then 2.
category One of tools, data, games, language, server, other. Anything else becomes other.
icon, screenshots Paths inside the package (served from jsdelivr) or absolute URLs.
serverPackages Server-side packages that go with the plugin (npm, pypi or nuget). They are listed with their install command by pkg info and on the marketplace; pkg does not install them.

2. Publish to npm

shell 
npm run build
npm publish --access public

3. Submit it

The indexer finds packages with the keyword every 30 minutes. To queue yours at once, submit its name from any Qodalis CLI terminal, or with the form on plugins.qodalis.com/publish:

Terminal 
pkg publish @acme/cli-weather

pkg publish only sends the package name (it does not publish to npm) and is rate-limited.

4. Review

A moderator checks the first version of a plugin before it is listed:

  • the bundle is a browser build that registers an ICliModule;
  • the commands do what the description says, and nothing else (no hidden network calls, no reading of unrelated storage);
  • name, description, category and links are accurate.

Publishers whose plugins were reviewed can be marked verified (✓ in pkg browse); their new versions are listed as soon as they are indexed. Other new versions wait for review. A version can later be flagged or unlisted: pkg add refuses it and pkg check warns users who installed it.

Versions and compatibility

The @qodalis/cli-core peer range decides which CLIs a version runs on, so set it honestly: to the oldest core you built and tested against (^2.8.0 when you use an API added in 2.8.0), not to *. The marketplace and pkg trust it.

  • pkg add installs the newest listed version whose apiVersion matches the running CLI and whose core peer range accepts the running @qodalis/cli-core version (^, ~, >=, <, x-ranges and ||). A version that does not fit is refused with the reason (needs CLI 2.9.0 or newer) and the newest one that works; pkg check and pkg update never offer it.
  • The CLI downloads the bundle from the npm CDNs and compares its SHA-384 with the hash the marketplace recorded. Republishing the same version is impossible on npm, so a mismatch means the file changed after review: the install stops. The hash is saved and checked again at every start.
  • Deprecating a version on npm, or unpublishing it, unlists it in the marketplace at the next index.

Without the marketplace

A package the marketplace does not list still installs by its full name (pkg add @acme/cli-weather) with a warning that it was not reviewed, unless the host set marketplaceOnly. Hosts can also point the CLI at their own marketplace: see Configuration → Plugin marketplace.

The marketplace API

A marketplace is identified by its base URL (https://plugins.qodalis.com/); the API lives under <base>api/v1/qcli/marketplace. Any server that answers these public endpoints can serve as a private marketplace (packageSources.marketplace). Responses are JSON, errors are { "error": "<text>" } with a 4xx/5xx status, and the CLI sends no credentials, so allow CORS from the pages that embed the terminal.

Request Answer
GET /plugins?query=&category=&apiVersion=&coreVersion=&page=1&pageSize=24&sort= Page<MarketplacePluginSummary>: listed plugins. query matches name, short name, description and tags (all words). sort: relevance, downloads, updated, name. pageSize 1-100.
GET /plugins/{name}?apiVersion=&coreVersion= MarketplacePlugin, 404 when not listed. {name} is URL-encoded (%40acme%2Fcli-weather).
GET /plugins/{name}/versions/{version} MarketplaceVersion (listed or flagged), 404 otherwise
GET /resolve?name= { matches: MarketplacePluginSummary[] }: listed plugins whose name or short name equals the input, an official one first
GET /categories { categories: { id, count }[] }
GET /stats { plugins, publishers, weeklyDownloads, indexedAt }
POST /submissions Body { "name": "<npm name>" } → 202 { status: 'queued' | 'known', plugin?: { name, status } }; 400 for an invalid name, 429 when rate limited
TypeScript 
interface MarketplaceVersion {
  version: string;           // semver
  apiVersion: number;        // module API the bundle needs (today 2)
  coreRange: string | null;  // peer range on @qodalis/cli-core
  bundle: string;            // path inside the package, e.g. "umd/index.global.js"
  integrity: string;         // "sha384-<base64>" of the bundle's bytes
  size: number;
  publishedAt: string;       // ISO date
  status: 'pending' | 'listed' | 'flagged' | 'unlisted' | 'rejected';
  note?: string;             // why it was flagged or unlisted
  deprecated?: string;
}

interface MarketplacePluginSummary {
  name: string;              // npm name
  shortName: string;         // "@acme/cli-weather" -> "weather"
  description: string;
  category: 'tools' | 'data' | 'games' | 'language' | 'server' | 'other';
  tags: string[];
  publisher: { id: string; name: string; verified: boolean };
  official: boolean;
  featured: boolean;
  icon?: string;
  downloads: { weekly: number };
  latest: string | null;     // newest listed version
  compatible: boolean;       // a listed version fits apiVersion and coreVersion
  version: string | null;    // newest listed version that fits
  reason?: string;           // why none fits: "needs CLI API 3 (this CLI has 2)"
  updatedAt: string;
}

interface MarketplacePlugin extends MarketplacePluginSummary {
  status: 'listed';
  author?: string;
  homepage?: string;
  repository?: string;
  license?: string;
  screenshots: string[];
  serverPackages: { ecosystem: 'npm' | 'pypi' | 'nuget'; name: string; install: string }[];
  readme: string;            // markdown, rendered without raw HTML
  versions: MarketplaceVersion[]; // newest first: listed and flagged
  createdAt: string;
}

interface Page<T> { items: T[]; total: number; page: number; pageSize: number }

pkg checks every version itself too (API, core range, status, hash), so a private marketplace only has to report what it knows.
