It takes six steps: run a server, give it an https address the phone can reach, allow the app's origin, link it with server add, then use it. The same steps work for the PWA and for this site's terminal. For the options apps and servers offer developers, see {{ 'sidebar.server-integration' | translate }}.

1. Run a server

Pick the Node, .NET or Python server. Use one with the users and admin plugins: they add sign-in, API tokens and the approval page that Approve in the browser needs (servers 1.0.0-beta.25 or later). The demo servers and their Docker images include both.

Docker (pick one) 
docker run -p 8047:8047 ghcr.io/qodalis-solutions/cli-server-node
docker run -p 8046:8046 ghcr.io/qodalis-solutions/cli-server-dotnet
docker run -p 8048:8048 ghcr.io/qodalis-solutions/cli-server-python

From the workspace with all three servers, ./docker-run-all.sh starts them together on ports 8046, 8047 and 8048. The demos sign in as root, with the password admin (Node, Python) or root (.NET): change it (passwd in the dashboard's Terminal) before the server is reachable from the internet. Check it from the computer: http://localhost:8047/qcli/admin opens the dashboard.

To build your own server instead, follow the Node, .NET or Python guide and add the users and admin plugins.

2. Make it reachable from the phone

localhost on the phone is the phone itself. The phone needs an address that leads to your computer, and in practice that address must be https with a certificate the phone trusts.

Why plain http on the LAN does not work

server add accepts http://192.168.1.20:8047 for private addresses after a confirmation, but the page the terminal runs in decides whether the requests leave:

TerminalPage originhttp://192.168.x.x server
Android apphttps://localhostBlocked: the WebView forbids mixed content (allowMixedContent: false) and Android blocks clear-text traffic by default
PWAhttps://qodalis-solutions.github.ioBlocked: browsers block http requests and ws:// sockets from https pages (mixed content)
This docs sitehttps://cli.qodalis.comBlocked, for the same reason
A page served over http (a local dev server)http://…Works

When it is blocked, server add warns This page is served over https: the browser may block requests to an http server and then fails with Cannot reach … Failed to fetch. Self-signed certificates do not help either: the WebView and the browsers reject them. Use one of these instead; each gives an https address with a valid certificate and passes WebSockets through, so the shell works too:

  • Tailscale (private, nothing exposed to the internet): install Tailscale on the computer and on the phone, enable HTTPS certificates for your tailnet, then run 
    tailscale serve --bg 8047
    The server is at https://<computer>.<tailnet>.ts.net for your devices only.
  • Cloudflare Tunnel (public): a quick tunnel needs no account and prints an https://….trycloudflare.com address: 
    cloudflared tunnel --url http://localhost:8047
    Anyone with the address reaches the server's sign-in, so change the default password first. A named tunnel gives a fixed address on your own domain.
  • A reverse proxy on a machine with a domain name, for example Caddy, which gets the certificate itself:
    Caddyfile
    cli.example.com {
    reverse_proxy localhost:8047
}

3. Allow the app's origin

The terminal calls the server from its own origin, so the server must allow that origin for CORS and WebSocket upgrades; otherwise the requests are refused and the terminal reports the server as unreachable. Add the origins you use:

TerminalOrigin to allow
Android apphttps://localhost
PWAhttps://qodalis-solutions.github.io
This docs sitehttps://cli.qodalis.com

The server's own dashboard (/qcli/admin) is same-origin and needs no entry.

ServerIn codeDemo and Docker image
NodecreateCliServer({ allowedOrigins: [...] })QCLI_ALLOWED_ORIGINS, comma-separated; replaces the demo's list
.NETcli.SetAllowedOrigins(...) in AddCliQCLI_ALLOWED_ORIGINS, comma-separated; added to the demo's list
PythonCliServerOptions(allowed_origins=[...])No variable: edit allowed_origins in demo/main.py
Docker (Node) 
docker run -p 8047:8047 \
  -e QCLI_ALLOWED_ORIGINS=https://localhost,https://qodalis-solutions.github.io,https://cli.qodalis.com \
  ghcr.io/qodalis-solutions/cli-server-node
server.ts (Node) 
createCliServer({
    allowedOrigins: ['https://localhost', 'https://qodalis-solutions.github.io', 'https://cli.qodalis.com'],
    // ...
});

4. Link it from the app

In the app, run server add with the server's https address:

Terminal 
$ server add https://my-pc.tailnet-1234.ts.net
Qodalis CLI server 1.0.0-beta.29 https://my-pc.tailnet-1234.ts.net (linux · shell · streaming · sign-in required)
How do you want to link it?
  Open the server in the browser and approve (recommended)
  Paste an API token
  Sign in with user and password

Pick one of the three ways to sign in:

  • Approve in the browser (recommended): the terminal prints a link to the server's approval page with a code such as ABCD-2345 and opens it. Sign in there (the phone's browser, or open the same link on your computer), check that the page shows the same code and approve. The terminal receives an API token for your account and connects. Your password never goes through the app.
  • Paste an API token: create one on the server, on the dashboard's Tokens page or with token create phone in a terminal signed in to the server, copy the qcli_pat_… value and paste it at the hidden prompt. Use this when the phone cannot open the approval page.
  • User and password: the terminal signs in once, creates an API token named after the device and signs the session out. Only the token is kept.

Then choose a name for the server (one is suggested from the address). server add home https://… gives the name up front, --default makes it the default server, and --no-browser skips the browser option.

5. Use it

  • server list shows the server as linked, with its status and number of commands.
  • Its commands run like local ones: echo hello, or home:echo hello to pick the server when a local command has the same name. server commands home lists them.
  • ssh home opens a shell on the server, when the server enables the shell and your user has the shell:execute permission (root does in the demos).
  • The server's files, data explorer, jobs and logs are on its dashboard (/qcli/admin), which also works in the phone's browser.

The link survives restarts. The token is kept on the phone encrypted with a Web Crypto key that cannot be read out (IndexedDB), is never shown again and never written to the command history. Apps that provide ICliSecretStore_TOKEN keep it in the platform's secure storage (Android Keystore) instead.

6. Troubleshooting

Start with server status home: it pings the server and lists what to check when it is unreachable.

SymptomCause and fix
Cannot reach … Failed to fetchWrong address or port, the server is not running, or the address is http (see step 2). Open the same address in the phone's browser: /api/qcli/versions should answer with JSON
Works in the phone's browser, not in the appThe app's origin is not allowed (step 3). The browser's address bar sends no Origin, so CORS only shows up in the app
Times out on the LAN or through TailscalePhone and computer are on different Wi‑Fi networks (a guest network isolates devices), Tailscale is off on one of them, or the computer's firewall blocks the port
is not a Qodalis CLI serverThe address leads to something else, for example the proxy's default page or a different port
cannot link through the browserThe server has no users plugin or is older than 1.0.0-beta.25: use server add --no-browser
Server 'home' rejected its tokenThe token expired or was revoked (token revoke): paste a new one with server edit home --token, or run server add again
The server movedserver edit home --url https://new-address

server remove home unlinks a server and deletes its token from the phone; the token stays valid on the server until it expires, so revoke it there with token revoke. server forget-all unlinks every linked server.
