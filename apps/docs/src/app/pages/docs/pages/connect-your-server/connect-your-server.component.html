You need three things: a Qodalis CLI server, an https address for it, and the app's origin allowed on the server. Then server add links it in a minute. The same steps work for the PWA and for this site's terminal. For the options apps and servers offer developers, see {{ 'sidebar.server-integration' | translate }}.

1. Run a server

Use the Node, .NET or Python server, wherever it can run: a hosting provider or cloud, a virtual server, your company's servers, or a machine at home. Include the users and admin plugins: they add sign-in, API tokens and the approval page that Approve in the browser needs (servers 1.0.0-beta.25 or later). The Docker images include both:

Docker (pick one) 
docker run -p 8047:8047 ghcr.io/qodalis-solutions/cli-server-node
docker run -p 8046:8046 ghcr.io/qodalis-solutions/cli-server-dotnet
docker run -p 8048:8048 ghcr.io/qodalis-solutions/cli-server-python

The images start with a root user whose password is admin (Node, Python) or root (.NET). Change it before the server is reachable from other devices: sign in to the dashboard at /qcli/admin and run passwd in its Terminal.

To add the CLI to your own application instead, follow the Node, .NET or Python guide and add the users and admin plugins.

2. Give it an https address

The phone reaches the server through an address such as https://cli.example.com. It must use https with a certificate the phone trusts, and the phone must be able to reach it from its network.

Why plain http does not work

server add accepts http://192.168.1.20:8047 for private addresses after a confirmation, but the page the terminal runs in decides whether the requests leave:

TerminalPage originhttp:// server
Android apphttps://localhostBlocked: the WebView forbids mixed content and Android blocks clear-text traffic
PWAhttps://qodalis-solutions.github.ioBlocked: browsers block http requests and ws:// sockets from https pages (mixed content)
This docs sitehttps://cli.qodalis.comBlocked, for the same reason

When it is blocked, server add warns This page is served over https: the browser may block requests to an http server and then fails with Cannot reach … Failed to fetch. Self-signed certificates do not help either: the WebView and the browsers reject them. (localhost does not help: on the phone it is the phone itself.)

Ways to get one

Serve the CLI server like any web application:

  • Your hosting platform's https: most hosting and container platforms give an app an https address and a certificate.
  • A reverse proxy or load balancer in front of the server, on a domain name, with a certificate from a public authority (Let's Encrypt or your provider's).
  • A VPN or tunnel service that gives devices an https address, for a server that should not be on the public internet. The phone then needs the same VPN.

Whichever you use, it must pass WebSocket upgrades through to the server: the shell and live events use them. To check, open https://cli.example.com/api/qcli/versions in the phone's browser: it answers with JSON.

3. Allow the app's origin

The terminal calls the server from its own origin, so the server must allow that origin for CORS and WebSocket upgrades; otherwise the requests are refused and the terminal reports the server as unreachable. Add the origins you use:

TerminalOrigin to allow
Android apphttps://localhost
PWAhttps://qodalis-solutions.github.io
This docs sitehttps://cli.qodalis.com

The server's own dashboard (/qcli/admin) is same-origin and needs no entry.

4. Link it from the app

In the app, run server add with the server's address. The terminal checks the server and asks how to sign in:

Pick one of the three ways to sign in.

Approve in the browser (recommended)

The terminal shows a code and opens the server's approval page in the browser. Sign in there with your account on the server, check that the page shows the same code, and approve. You can also open the link on another device, such as your computer. The terminal receives an API token for your account and connects; your password never goes through the app.

After the approval, name the server (one is suggested from the address) and it is linked:

Paste an API token, or user and password

  • Paste an API token: create one on the server, on the dashboard's Tokens page or with token create phone in a terminal signed in to the server, copy the qcli_pat_… value and paste it at the hidden prompt. Use this when the phone cannot open the approval page.
  • User and password: the terminal signs in once, creates an API token named after the device and signs the session out. Only the token is kept.

server add myserver https://… gives the name up front, --default makes it the default server, and --no-browser skips the browser option.

5. Use it

  • The server's commands run like local ones. When the app has a command with the same name (echo, hash, ...), the local one runs: put the server's name in front, myserver:echo hello. server commands myserver lists them.
  • server list shows the server as linked, with its status and number of commands.
  • ssh myserver opens a shell on the server, when the server enables the shell and your user has the shell:execute permission.
  • The server's files, data explorer, jobs and logs are on its dashboard (/qcli/admin), which also works in the phone's browser.

The link survives restarts, and the terminal keeps checking the server: when it goes down and comes back, its commands return on their own. The token is kept on the phone encrypted with a key that cannot be read out, is never shown again and never written to the command history.

6. Troubleshooting

Start with server status myserver: it checks the server and lists what to look at when it is unreachable.

SymptomCause and fix
Cannot reach … Failed to fetchWrong address, the server is not running, or the address is http (see step 2). Open /api/qcli/versions at the same address in the phone's browser: it should answer with JSON
Works in the phone's browser, not in the appThe app's origin is not allowed (step 3). The browser's address bar sends no origin, so this only shows up in the app
Times outThe phone cannot reach the server from its network: a firewall blocks the port, or the server is on a private network or VPN the phone is not connected to
Commands work, the shell does notThe proxy in front of the server does not pass WebSocket upgrades through (step 2), or your user lacks shell:execute
is not a Qodalis CLI serverThe address leads to something else, for example the proxy's default page
cannot link through the browserThe server has no users plugin or is older than 1.0.0-beta.25: use server add --no-browser
Server 'myserver' rejected its tokenThe token expired or was revoked (token revoke): paste a new one with server edit myserver --token, or run server add again
The server movedserver edit myserver --url https://new-address

server remove myserver unlinks a server and deletes its token from the phone; the token stays valid on the server until it expires, so revoke it there with token revoke. server forget-all unlinks every linked server.
