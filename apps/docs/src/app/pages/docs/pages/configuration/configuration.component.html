Server Configuration

Each entry in the servers array uses the CliServerConfig type:

Option Type Default Description
name string (required) Unique identifier. Server commands are prefixed with this name.
url string (required) Base URL, e.g. "http://localhost:8047"
enabled boolean true Set to false to skip this server on startup
headers Record<string, string> | () => Record<string, string> {} Static or dynamic headers sent with every HTTP request. Use a function for rotating tokens (e.g. JWTs). WebSockets never carry them: the browser cannot set socket headers, so the client trades them for a single-use ticket (POST /api/v1/qcli/sessions/ws-ticket, users plugin) and connects with ?ticket=. A server without that endpoint gets unauthenticated sockets and a console warning. With the users module loaded for the server, leave headers out: the module signs requests and sockets itself.
timeout number 30000 Request timeout in milliseconds
unsafeHeadersInWebSocketUrl boolean false Deprecated. Copy headers into WebSocket URLs as _header_<name> query parameters, as up to 2.0.0. Tokens in URLs end up in access, proxy and CDN logs and in browser history; use it only for a server that still needs it, such as a shell token without the users plugin. 
servers: [
    { name: 'node', url: 'http://localhost:8047' },
    {
        name: 'api',
        url: 'https://api.example.com',
        headers: () => ({ Authorization: 'Bearer ' + getToken() }),
        timeout: 10000,
    },
]

Panel Configuration

When using the <cli-panel> component, pass panel-specific options via the options prop. The CliPanelOptions type extends CliOptions with CliPanelConfig properties:

Option Type Default Description
isCollapsed boolean true Whether the panel starts collapsed
isHidden boolean false Whether the panel starts hidden (showing only the small tab)
position 'bottom' | 'top' | 'left' | 'right' 'bottom' Panel position relative to the viewport
closable boolean true Whether the close button is shown
resizable boolean true Whether the panel can be resized by dragging
hideable boolean true Whether the hide button is shown
hideAlignment 'start' | 'center' | 'end' 'center' Alignment of the hidden-mode tab along the viewport edge
syncTheme boolean false Auto-sync panel chrome colors with the active terminal theme
theme 'dark' | 'light' | 'auto' | string | CliPanelTheme 'dark' Look of the panel and its terminals; see Panel themes 
const panelOptions: CliPanelOptions = {
    position: 'right',
    isCollapsed: false,
    isHidden: false,
    closable: true,
    resizable: true,
    syncTheme: true,
    hideAlignment: 'end',
};

Panel themes

theme sets the look of the panel (header, tabs, menus, hide tab) and of every terminal in it. A plain <cli> takes the same option for its terminal.

Value Result
'dark' (default) Built-in dark palette with the default terminal theme
'light' Built-in light palette with the light terminal theme
'auto' Light or dark, following the system's prefers-color-scheme; switches live
A terminal theme name 'dracula', 'nord', 'solarizedLight', ... (see theme list): the terminals use it and the panel's colors are derived from it
CliPanelTheme Your own colors over a base palette: base ('light', 'dark' or 'auto'), terminal (a theme name or xterm colors), colors, fontFamily, radius

colors takes any of background, headerBackground, border, text, textSecondary, accent, hoverBackground, activeBackground, danger and shadow; the ones left out come from the base palette. 

const panelOptions: CliPanelOptions = {
    theme: {
        base: 'light',
        colors: { accent: '#0f766e', headerBackground: '#f0fdfa', border: '#99f6e4' },
        fontFamily: 'Inter, sans-serif',
        radius: '10px',
    },
};

Following the app's own theme

Pass the app's light/dark setting through theme: the panel and its open terminals restyle when it changes. In React and Vue a re-render is enough; in Angular pass a new options object. Any framework can also call setTheme(theme) on the panel ref.

React 
const { dark } = useAppSettings();
<CliPanel options={{ theme: dark ? 'dark' : 'light' }} />

With a theme from the app, the theme someone saved with the theme command is not restored on the next start; the command still changes the terminal for the session. Without a theme option nothing changes: terminals keep the saved theme and the panel uses the dark palette, or colors derived from the terminal with syncTheme: true.

CSS variables

The theme is applied as CSS custom properties on the panel, its hide tab, its dropdowns and its context menu, so a stylesheet can also override them: 

.cli-panel-wrapper,
.cli-panel-hide-tab,
.cli-panel-context-menu,
.cli-panel-services-dropdown {
    --cli-panel-accent: #e11d48;
    --cli-panel-radius: 0;
}

The variables: --cli-panel-bg, --cli-panel-header-bg, --cli-panel-border, --cli-panel-text, --cli-panel-text-secondary, --cli-panel-accent, --cli-btn-hover-bg, --cli-btn-active-bg, --cli-panel-danger, --cli-panel-shadow, --cli-panel-font and --cli-panel-radius. Inline theme values win over a stylesheet, so set either the option or the variables for a given color.

Phones and tablets

  • The resize grip works with touch and is larger on touch screens; it stays visible while the panel is open.
  • When the on-screen keyboard opens, the panel moves above it and shrinks to the visible area, so the prompt stays in view while typing. It is never taller than the space it has and stays below the status bar of apps that draw under it.
  • An app with its own bottom bar (tabs, a toolbar) docks the panel above it with --cli-panel-bottom-offset instead of overriding bottom, so the panel still moves above the keyboard: :root { --cli-panel-bottom-offset: 64px; }
  • Up to 600px wide, the header keeps the title, the run state and the buttons on one line.
